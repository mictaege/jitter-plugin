# AGENTS.md — jitter-plugin

## Project purpose
`jitter-plugin` is a Gradle plugin to build and distribute different flavours of an application from
a single source base — a code-level alternative to forking, feature-toggles, or preprocessors. It
uses Java Annotation Processing backed by the [Spoon](http://spoon.gforge.inria.fr/index.html)
analysis/transformation framework (via `spoon-gradle-plugin`) to transform source code, based on
annotations defined in `jitter-api`, before final compilation.

Part of the jitter/spoon family: this plugin is the integration point — it depends on `jitter-api`
for its annotation contract and on `spoon-gradle-plugin` for the underlying source transformation.
[`eval.jitter`](https://github.com/mictaege/eval.jitter) is the reference example/demo consumer of
this plugin.

## Technical stack
- Languages: mixed Groovy (`src/main/groovy`) and Java (`src/main/java`) plugin sources, plus Java
  tests (`src/test/java`).
- Build tool: Gradle (Kotlin DSL, `build.gradle.kts`), `java-gradle-plugin` — build via `./gradlew`.
- Plugin packaging: `com.gradle.plugin-publish`, published to the Gradle Plugin Portal.
- Key dependencies: `spoon-gradle-plugin` (implementation), JUnit Jupiter (JUnit BOM-managed) for
  tests.
- Resources: `src/main/resources/META-INF/gradle-plugins` registers the plugin id; a generated
  `jitter-plugin.properties` (written during `processResources`) exposes the plugin's own version.
- Release/publishing: `org.jreleaser`, publishing to Maven Central under group `io.github.mictaege`.
- License: Apache License 2.0.

## Project semantics / domain notes
- Core domain concept: "flavours" — different build/runtime variants of the same application,
  selected via Gradle tasks generated by this plugin (e.g. `flavourESA`, `flavourNASA`); see
  `eval.jitter` for a concrete example.
- The transformation pipeline is: application code annotated with `jitter-api` annotations → Spoon
  processing (via `spoon-gradle-plugin`) → flavour-specific compiled output.
- This plugin composite-builds/depends on `../jitter-api` and `../spoon-gradle-plugin` as sibling
  checkouts — keep that relative project layout in mind for local multi-project development.

## Working conventions
- Run `./gradlew test` before submitting changes; for end-to-end verification, build and run
  `eval.jitter` against a locally published version of this plugin.
- Coordinate version bumps with `jitter-api` and `spoon-gradle-plugin`, since this plugin's
  correctness depends directly on both.
