## 3. Verify-side implementation

- [x] 3.1 Added `MetadataVerifier` (ASM-only scan of the `@kotlin.Metadata` `d2` table: violation when a removed class descriptor `L<internalName>;` occurs, or when the class's own d2 still names a removed member of that owner) and wired it into `JitterVerifyTask.run()` next to `ReferenceVerifier.findDanglingReferences`, failing with a `jitter: `-prefixed error. Verified: `MetadataVerifierTest` 4/4 green (was 2 red violation cases + 2 guards).
- [x] 3.2 Refined the verifier after the ologis e2e (task 4.3) exposed a false positive: a `d2` reference to a removed class/member is a violation only when the class's own bytecode no longer references it either (bytecode refs collected from descriptors, signatures, inner classes, super/interfaces and instruction operands outside annotations; violations deduplicated). Declaration-level references the bytecode keeps - e.g. `ScriptDTO.scriptType: ScriptType` in ologis, where the whole `scriptengine` package is gated - are tolerated, mirroring `ReferenceVerifier`, which only visits instructions. Verified: `MetadataVerifierTest` 5/5 green, incl. the new tolerance case (bytecode reference to a removed class passes) and the metadata-only case (method stripped from bytecode via ASM, d2 untouched, is reported).
